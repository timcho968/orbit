# План

## Шаги

1. **Favicon-хранилище + пункт меню** — при `onReceivedIcon` сохранять favicon
   в `files/favicons/<host>.png`; в меню появляется пункт «Add to Home screen»
   (строка `add_to_home` уже есть). Готово = AC-1, AC-2.

2. **Создание/обновление ярлыка** — `ShortcutManagerCompat.pushDynamicShortcut`:
   id = хост, label = заголовок страницы, иконка = favicon (скейл до 96dp) или
   иконка Orbit, intent → WebappActivity с URL. Повторное добавление хоста
   обновляет существующий ярлык. Готово = AC-1, AC-2.

3. **WebappActivity** — новая activity в манифесте (`exported=false`,
   `taskAffinity="com.orbit.browser.webapp"`, `launchMode="singleTask"`):
   WebView на весь экран, никакого UI, immersive-статусбар (свайп показывает),
   адблок через общий `AdblockService`, «назад» по истории страницы,
   `onNewIntent` для повторного тапа по ярлыку, скачивания через общий helper.
   Готово = AC-3, AC-4, AC-5, AC-6.

4. **Сборка и верификация на устройстве** — пересборка пайплайном из brief,
   установка, фактическая проверка всех AC на телефоне (uiautomator/dumpsys/logcat).
   Готово = AC-1…AC-6 все зелёные.

## Acceptance criteria

AC-1: Дано — открыт сайт (у него есть favicon).
      Когда — в меню выбран «Add to Home screen», затем тот же хост добавлен ещё раз.
      Тогда — на рабочем столе появляется ярлык с иконкой-фавиконом, и после
      повторного добавления `dumpsys shortcut`/ShortcutManager показывает ровно
      один ярлык на этот хост (дублей нет).

AC-2: Дано — открыт сайт без favicon.
      Когда — выбран «Add to Home screen».
      Тогда — ярлык создан с дефолтной иконкой Orbit, без крашей.

AC-3: Дано — созданный ярлык yummyani.
      Когда — тап по ярлыку на рабочем столе.
      Тогда — открывается WebappActivity: страница занимает экран, адресной строки
      и панелей нет (uiautomator не находит `id/urlBar` и `id/bottomBar`),
      статусбар скрыт (в dump `isStatusBarVisible=false` или его отсутствие).

AC-4: Дано — webapp открыт, внутри сайта перешли на 2-ю страницу.
      Когда — жмём «назад» один раз, потом ещё раз.
      Тогда — первый раз возврат по истории сайта (URL меняется на предыдущий),
      второй — webapp закрывается (activity уничтожена).

AC-5: Дано — webapp уже запущен.
      Когда — повторный тап по ярлыку.
      Тогда — новый экземпляр не создаётся (одна карточка в переключателе задач,
      `dumpsys activity` показывает одну WebappActivity), URL открывается заново.

AC-6: Дано — открыта тестовая страница блокировщика (d3ward.github.io/toolz/adblock).
      Когда — загружена в webapp-режиме.
      Тогда — страница сообщает ≥90/100 заблокировано (текст читается uiautomator-ом),
      т.е. адблок-движок работает в webapp.

## Non-goals

- PWA-manifest.json не читается
- Иконки ярлыков не обновляются после создания
- Пункта «Remove shortcut» в меню нет
- Один ярлык = один хост (несколько ярлыков на сайт не делаем)

## Открытые вопросы

- Нет. Риски из brief (ярлыки на Quickstep, жизненный цикл AdblockService между
  activity) закрываются шагом 4/слайсом на реальном устройстве, отдельные спайки
  не требуются — если AC-1/AC-6 упадут, возврат на стадию 3 с конкретным вопросом.
